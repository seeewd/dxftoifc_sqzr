# POC_2D_TO_BIM — 프로젝트 컨텍스트

> 본 문서는 프로젝트의 **시작·맥락·전략적 위치**를 설명한다. 구현 전 `PROJECT_CONTEXT.md` → `POC_2D_TO_BIM_DEV_SPEC.md` 순으로 읽어라.

## 한 줄 정의
정리된 CAD 평면도(DXF)에서 구조 부재를 인식해 BIM(IFC)으로 자동 변환하는 파이프라인. **CAD→BIM 제품의 코어 엔진.**

## 주체
- **SquareZero(SQZR)** — 한국 AEC(건축·엔지니어링·건설) 테크 스타트업.
- 의사결정: **Hong (CPO, 단일 기술 결정권자).** 워크플로우 = Claude로 기획/설계 → 스펙(.md) → **Claude Code가 구현**.
- 설계 철학 **"vibe BIMing"**: 엔지니어는 의도·판단에 집중하고 AI가 BIM 기술 실행을 담당. **유저 개입 최소화**가 제품 목표 → 인식·자동화·디폴트가 핵심.

## 왜 이 프로젝트인가 (시작 맥락)
- 도면→BIM 모델링은 수작업 비용이 크다. 글로벌 CAD→BIM 툴은 **한국 표준/관행 로컬라이징 부재**로 현장에서 실패한다(기술 격차가 아니라 로컬라이징 격차).
- 시공사·설계사의 실수요: BIM을 통한 **정확성 검토 + 물량산출**.
- 핵심 기술 난제는 출력 포맷이 아니라 **2D 기하 → 시맨틱 객체 복원**(기둥/벽 인식, 센터라인, 정션 정리). 그래서 출력은 **IFC(개방표준)로 고정** — Revit/ArchiCAD/Tekla 공통분모 + 헤드리스 반복 속도 확보.

## 로드맵 (지평)
1. **[즉시] 다음주 Claude 해커톤 시연.** DXF→IFC, **기둥 풀패스 + 입력 UI + 디버그 로그**. 데모 문장: "도면 넣으면 기둥이 IFC로 선다."
2. **[다음] CAD→BIM (골조 only).** 타겟 = **시공사: 대우 BIM, 이안 설계 팀.** 실시설계도면 → 골조 BIM, 정확성검토·물량산출.
3. **[장기] NEW BIM 툴의 보조 기능.** SquareZero가 곧 착수할 신규 BIM 저작 툴에 이 변환 엔진이 **내장 기능**으로 편입.

## 이 PoC가 증명할 것
출력 포맷·UI가 아니라 **"messy 실무 DXF에서 시맨틱 복원이 된다"**. 기둥 한 종을 풀패스로 뚫으면 벽·슬래브는 같은 기계의 변주 → **골조 전체로 확장 가능함**을 입증하는 게 목적.

> **범용 엔진 원칙:** 특정 도면 한정 규칙을 박지 않는다. 인식은 **① 인벤토리 추출 → ② signal-agnostic 자동추론 + 유저 가이드 매핑 → ③ 기하 기반 측정/배치**. 즉 "도면마다 신호(레이어/블록/그룹)가 어디 있든" 유저가 한 번 지목하면 동일 엔진이 처리. 유저 개입 최소화("vibe BIMing")는 *자동 제안의 정확도*로 달성한다. (구현 세부는 DEV_SPEC §0·§5.)

## 성공 기준 (지평별)
- **해커톤:** 실제 지하주차장 DXF → 기둥 IFC가 뷰어에서 정위치·정크기. 데모 가능.
- **골조 제품:** 시공사 도면으로 골조 BIM 산출 + 도면 내부 모순 플래그(정확성검토의 씨앗).
- **BIM 툴:** 변환이 저작 워크플로우에 매끄럽게 들어가 유저 검토 최소화.

## 작업 규약 (Hong)
직설적·근거 기반 피드백. 빈 칭찬/과장 금지(맞으면 "맞다", 합리적이면 "합리적이다"로 사실 판정은 명확히). 맞으면 맞다고, 틀리면 틀리다고.
